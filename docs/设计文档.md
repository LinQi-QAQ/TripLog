# 出行记（TripLog）产品设计文档

> 自用安卓 app。记录我的出行信息：车次、航班、大巴、地铁，能识别车票截图，用 AI 生成结构化行程。
> 技术栈：Kotlin + Jetpack Compose + Room + Material 3。

---

## 一、定位与原则

一句话：把「翻相册找车票截图」变成「一眼看到所有行程，出发前自动提醒」。

自用意味着三件事：
1. 不需要账号体系，不需要登录，不需要联网也能用（AI 识别是唯一需要联网的功能）。
2. 数据全部在本机，导出和备份是我自己的事，app 只负责给出导出文件。
3. 界面优先给「我」看，不迎合大众审美，但保持干净，因为要看很久。

设计原则：
- 一屏内能看完最近的一次出行，不用点进去。
- 添加一次行程不超过 30 秒，走 AI 识别只要 10 秒。
- 所有数据本地存储，不上传任何服务器。
- 视觉延续个人主页的极简路子：白底、黑字、无彩色块堆砌，颜色只用来传达信息（交通工具类型、紧急程度）。

## 二、用户与场景

使用者只有我一个。典型场景：

场景 A：刚买到票，截图发到微信，想存起来以后查。
场景 B：出发前一天晚上，想知道明天几点走、在哪个站、坐哪个车次。
场景 C：到了车站，车次信息在 app 里，打开给工作人员看一眼。
场景 D：月底想回顾这个月跑了哪些地方。
场景 E：手里有一张纸质票的照片，不想手打字，让 AI 认。

## 三、功能清单

### P0 必须有（第一版就要能用）

F1 行程录入（手动）
- 字段：交通工具类型、出发地、目的地、出发时间、到达时间、编号（车次/航班号）、座位、票价、备注。
- 只有「类型、出发地、目的地、出发时间」是必填，其他都可空。
- 支持只填单程，也支持往返两条一起建。

F2 车票截图识别（AI 视觉）
- 入口：添加页的「识别车票」按钮，或相册选图，或直接拍照。
- 流程：选图 → 压缩 → 调视觉模型 → 返回结构化 JSON → 预填表单 → 我确认后保存。
- 识别结果里同时保留原图，行程详情页能看大图。
- AI 服务商可配置：接口地址、模型名、API Key，存在本机 EncryptedSharedPreferences，不上云。
- 识别失败或字段缺失时，表单照常打开，缺失字段留空让我手填，不阻断。
- 不配置 AI 时按钮置灰，其余功能完全不受影响。

F3 行程列表（时间线）
- 按出发时间倒序，未来行程排在最上面（「即将出发」分区），已结束的在下面（「历史」分区）。
- 每行显示：日期、时间、出发地 → 目的地、交通工具图标、编号。
- 支持筛选：全部 / 火车 / 飞机 / 汽车 / 其他。
- 支持搜索：出发地、目的地、编号，任意字段包含即命中。
- 左滑删除，长按多选批量删除（防误删，删除有确认）。
- 列表空态显示引导文字和添加按钮。

F4 行程详情
- 显示全部字段 + 车票原图（可点击放大）。
- 可编辑、可删除。
- 有车票截图的，详情页顶部显示缩略图条。

F5 本地持久化
- Room 数据库，版本可迁移。
- 图片存 app 私有目录，数据库只存路径，不存二进制。

F6 出发提醒
- 提前时间可选：1 小时 / 3 小时 / 1 天 / 不提醒。
- 用 AlarmManager 精确提醒，开机后能重建（BOOT_COMPLETED）。
- 点击通知直接跳到行程详情。
- 提醒文案：「还有 3 小时出发：G1234 上海虹桥 → 北京南」。

### P1 第二版

F7 数据导出：导出 JSON 和 CSV 到 Downloads，分享给其他 app。
F8 数据备份恢复：整库备份文件，换机用。
F9 统计页：本月出行次数、各交通工具占比、总里程（如有距离数据）。
F10 桌面小组件：显示最近一次出行，不用打开 app。
F11 常用地点：自动记录常去的站点，添加时快速选择。
F12 支持 OCR 离线兜底：ML Kit 文本识别，无网络时先识别文字让我自己对着填。

### P2 以后再说

F13 多段行程（换乘）合并成一次出行。
F14 自动从短信/邮件解析 12306 通知。
F15 日历视图。

## 五、AI 识别设计

### 5.1 为什么用可配置接口而不是写死某一家

三家各有限制：
- OpenAI 兼容接口（/v1/chat/completions，image_url 传 base64）生态最广，国内中转、DeepSeek、通义、智谱的兼容端点都能接，OpenRouter 一个 Key 用多家模型。
- Gemini 原生接口（generativelanguage.googleapis.com）图像理解强，有免费额度。
- Claude Messages 接口（/v1/messages）图像能力好。

做成配置化的：baseUrl + model + apiKey + 一个请求体模板。默认给 OpenAI 兼容格式，因为这个覆盖面最大。

### 5.2 请求设计

用 OpenAI 兼容 chat completions，messages 里放 system + user，user 的 content 是图片加提示词。

system 提示词要点（这个直接决定识别质量）：
- 只输出 JSON，不要 markdown 代码块围栏，不要任何解释文字。
- 字段固定，缺失填 null，不要猜测编造。
- 时间统一 ISO 8601 本地时间格式，不要时区后缀。
- 车次号保持原文，不要转写。
- 站名保留完整官方名，不要简称。

user 提示词：
「请识别这张车票截图，提取下面字段并以 JSON 返回：vehicle_type（train/flight/bus/other）、from_station、to_station、depart_time（YYYY-MM-DDTHH:mm）、arrive_time、number（车次或航班号）、seat、price、passenger、note。不要输出 JSON 以外的任何内容。」

temperature 设 0，减少编造。

### 5.3 返回解析

容错优先级：
1. 直接 JSON.parse。
2. 剥掉 ```json 围栏再 parse。
3. 用正则抓第一个 { 到最后一个 } 的子串再 parse。
4. 都失败：提示识别失败，表单正常打开留空，原图仍保留。

解析出的字段做校验：时间格式不对就当空；price 去除非数字字符；vehicle_type 不在枚举内就归 other。

### 5.4 图片处理

- 选图后先读 EXIF 旋转角度，转正。
- 长边压到 1568 像素以内（多数视觉模型的甜点区，再大反而被降采样）。
- 编码 JPEG 质量 85，base64 后控制在 4MB 以内。
- 压缩后的图存私有目录，详情页和列表缩略图都用压缩图，原图不留（省空间，也避免重复压缩）。

### 5.5 安全

- API Key 用 EncryptedSharedPreferences（AES256_GCM），不明文落盘。
- 请求走 HTTPS，允许自签证书的开关默认关闭。
- 不做任何形式的日志打印 Key。

## 六、数据模型

Trip 表：
- id（Long 主键自增）
- vehicleType（String，枚举 train/flight/bus/other）
- fromStation（String）
- toStation（String）
- departTime（Long，毫秒时间戳，可空）
- arriveTime（Long，可空）
- number（String，车次/航班号，可空）
- seat（String，可空）
- price（String，存字符串避免精度和货币混乱，可空）
- passenger（String，可空）
- note（String，可空）
- ticketImagePath（String，压缩图路径，可空）
- remindBeforeMinutes（Int，0 表示不提醒）
- reminded（Boolean，已提醒标记，改时间后重置）
- createdAt（Long）
- updatedAt（Long）

索引：departTime（列表排序）、fromStation、toStation、number（搜索）。

为什么时间存 Long 而不是字符串：排序、比较、算倒计时都要转成数字，存字符串每次都要 parse。展示时再格式化。

为什么 price 存 String：会有「¥123.5」「123.50 CNY」这种混合格式，也可能有货币符号，存数字还要额外记货币字段，自用场景字符串更省事。

## 七、技术方案

- 语言 Kotlin，最低 SDK 26（Android 8.0，覆盖 AlarmManager 精确闹钟的常规用法），target/compile 用 37（机器上已装）。
- UI：Jetpack Compose + Material 3，无 XML 布局。
- 架构：单 Activity + Navigation Compose，MVVM，ViewModel + StateFlow。
- 数据库：Room，KSP。
- 依赖注入：不用 Hilt，手写一个简单的 AppContainer，自用 app 引入 Hilt 的构建开销不划算。
- 网络：OkHttp + kotlinx.serialization。
- 图片：Coil。
- 时间：java.time（minSdk 26 满足，不用 desugaring）。
- 构建：Gradle Kotlin DSL，仓库走腾讯云 Gradle 镜像加速，阿里云 maven 实测 404 不用。

## 九、视觉规范

延续个人主页的极简路子，但按 Material 3 落地：

- 主色不用品牌彩色，用中性灰阶 + 一个强调色。强调色选墨蓝 #3B5B92，白底上够沉，不刺眼。
- 背景 #FFFFFF，卡片 #F7F7F5，分割线 #E6E6E1，主文字 #1A1A1A，次文字 #8A8A85。
- 字体：系统默认（苹方在安卓上没有，用思源黑体回退），标题 22sp/Medium，正文 15sp/Regular，辅助 13sp。
- 交通工具用线性图标 + 颜色区分：火车 #3B5B92、飞机 #5B7F9E、汽车 #7A8B5A、其他 #8A8A85。图标本身线性、1.5px 描边感。
- 圆角：卡片 12dp，按钮 10dp，输入框 10dp。
- 间距体系：4/8/12/16/24。
- 深色模式：背景 #121212，卡片 #1E1E1E，文字 #ECECEC，强调色提亮到 #7FA0D8。第一版就支持，不额外做工。
- 动效：只做淡入和位移，时长 200-300ms，不引入动画库。

## 十一、风险与对策

R1 Gradle 首次构建要下载一堆依赖，网络不稳会卡很久。
对策：仓库配腾讯云镜像；构建一次成功后缓存就在本机，后续快。

R2 模拟器没配好 GPU 加速可能起不来。
对策：已有 Medium_Phone_API_37.0，第一次启动若黑屏就切软件渲染。

R3 AI 接口各家返回格式有差异，JSON 可能有围栏或多余文字。
对策：三层解析容错，见 5.3。

R4 截图里信息不全（比如没有到达时间）。
对策：允许字段为空，识别只填有的，其余手填。

R5 API Key 存本机有泄露风险（root 机器）。
对策：EncryptedSharedPreferences；自用可接受；界面提示不要把 apk 随便装别人机器。

R6 Room 升级改字段会导致崩溃。
对策：先加 fallbackToDestructiveMigration 便于开发期，V1 定稿前把迁移策略改严。

### 和规划的偏差

1. **compileSdk 用 36 而不是原计划的 37**。AGP 8.13.0 只测到 36.1，
   用 android-37 会报 "Failed to find target with hash string 'android-37'"。
2. **工程放在 `C:\AndroidProjects\TripLog` 而不是 `工作项目\出行记`**。
   中文路径下 AGP 能用 overridePathCheck 强行编译，但单元测试的 classloader
   会 ClassNotFoundException，测试完全跑不了。这是硬性限制。
3. **额外发现并修复的一个设计缺陷**：列表排序方向。
   原设计按出发时间倒序，导致「即将出发」里三天后出发的排在十天后出发的后面，
   和最紧急置顶的直觉相反。已改成正序。
4. **统计页是后来加的**，原规划里排在第四批最后，实际做了完整一页。

### 风险项的实际结果

- **R1（Gradle 下载慢）**：确实如此。首次构建要下 Gradle 发行包和全部依赖。
  已用腾讯云镜像解决，Gradle 8.14.3 的 sha256 与官方一致。另外还发现
  Gradle 8.14.3 不支持 Android Studio 自带的 JDK 25，额外装了 JDK 21。
- **R2（模拟器可能起不来）**：实际情况比预想的严重得多，**这项没达成**。
  不是 GPU 加速问题，而是缺 AEHD 加速驱动（需管理员权限）。
  备选的纯软件模拟会卡死，ARM64 镜像方案被 emulator 硬拒（架构校验）。
  详见 README 的「模拟器现状」。
- **R3（AI 返回格式差异）**：确实存在，且比预想的更花哨。
  除了围栏和多余文字，模型还会把字符串字段写成对象或数组。
  原来的严格解析遇到这种就整次失败，已改成逐字段宽容取值。
- **R4（截图信息不全）**：已按设计处理，允许字段为空。
- **R5（Key 泄露）**：已用 EncryptedSharedPreferences。
- **R6（Room 升级崩溃）**：当前用 fallbackToDestructiveMigration，
  开发期方便。如果以后要保留数据升级，得改成正式迁移。
