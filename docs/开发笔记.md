# 出行记（TripLog）使用与开发说明

## 这是什么

自用的安卓 app，用来记录出行信息。核心能力：

1. 手动录入行程：车次、航班、汽车，站点、时间、座位、票价、乘车人、备注。
2. 车票截图识别：选一张车票截图，调 AI 视觉模型自动提取字段，预填表单，确认后保存。
3. 时间线展示：未来行程在上面（即将出发），历史行程在下面，支持搜索和按交通工具筛选。
   同一分区内按出发时间正序，最近期的排最前——「即将出发」里最紧急的在最上面。
4. 出发提醒：提前 1 小时 / 3 小时 / 1 天通知，开机后自动重建。
5. 左滑删除单条，长按多选批量删除。
6. 导出备份：整个库连车票图打包成 zip，可恢复。
7. 统计页：年度总览、交通工具占比条、常去城市排行、月度明细。
8. 全部数据存本机，不上传任何服务器。

工程位置：C:\AndroidProjects\TripLog
注意：工程必须放在纯英文路径下。原先放在 工作项目\出行记（中文），
AGP 虽然能靠 android.overridePathCheck 强行编译，但单元测试的 classloader
在中文路径下会 ClassNotFoundException，测试跑不了。所以搬到了这里。

## 怎么跑

模拟器这条路目前走不通，原因见下面「模拟器现状」。

现在能用的验证方式有三种：

方式一，装到手机（最快，推荐）：
手机开开发者模式（设置里连点版本号七次），进开发者选项打开 USB 调试，
插线到电脑，手机上允许调试，然后：
```
adb install -r app\build\outputs\apk\debug\app-debug.apk
```
详细步骤和功能核对清单见 `docs\真机验证指南.md`。

方式二，跑单元测试（已验证通过，无需任何设备）：
```
gradle :app:testDebugUnitTest
```
报告在 app\build\reports\tests\testDebugUnitTest\index.html。
覆盖 Room 数据层（Robolectric 跑真实 SQLite）、表单校验、AI JSON 容错解析、
模型输出宽容解析、备份格式、统计计算，以及 **Compose 界面渲染与交互**
（Robolectric 跑真实 Compose，验证按钮点得动、输入传得出去、文案显示得出来）。

方式三，跑插桩测试（需要真机或模拟器）：
```
gradle :app:connectedDebugAndroidTest
```
测备份 zip 的完整往返。插桩测试 APK 在 app\build\outputs\apk\androidTest\debug\。

说明：界面测试有两种。Robolectric 版在 JVM 上跑，不需要设备，
覆盖组件级渲染和交互；插桩版跑在真机上，覆盖需要真实文件系统和 zip 流的场景。

写 Compose 测试的几个实用经验：

1. FormField 的 label 和输入框是两个独立节点。label 是纯 Text 不能输入，
   输入框要按 placeholder 定位（`onNodeWithText("上海虹桥")` 找到的是输入框）。
2. 长表单里靠下的元素不在视口，`assertIsDisplayed` 会失败，
   要先 `performScrollTo()`。
3. 同一个测试里只能调一次 `setContent`，要测多种状态就合并到一次渲染里。
4. 中文测试方法名有空格会被 D8 dex 拒绝，要么加反引号且不含空格，
   要么干脆用拼音或英文。
5. 点按钮触发协程操作（比如删除）后，要轮询等状态变化，
   不能只 `waitForIdle()`。

方式三，Android Studio 里点 Run，选你的真机。

## AI 识别怎么配

第一次用之前必须配，否则识别按钮是灰的。路径：底部「我的」→ AI 设置。

三个字段：
- 接口地址：填到 /v1 这一层，例如 https://api.deepseek.com/v1、https://api.openai.com/v1、https://openrouter.ai/api/v1
- 模型名：必须支持图片输入。例如 gpt-4o-mini、gpt-4o、deepseek-vl2、qwen-vl-max-latest
- API Key：加密存在本机 EncryptedSharedPreferences，不明文落盘

填完点「测试连接」，返回「连接成功」就能用了。

实现用的是 OpenAI 兼容的 /chat/completions 格式，这是覆盖面最广的，
国内中转基本都兼容，一个 Key 一个地址就能换供应商。

识别容错（模型不守规矩是常态，三层兜底）：

1. stripFence：剥掉 ```json 围栏，截取第一个 { 到最后一个 }，
   吃掉「好的，结果如下：」「希望有帮助」这类前后废话。
2. parseLenient：逐个字段宽容取值。该给字符串的地方给了对象或数组，
   转成 JSON 文本塞进 note；给了数字或布尔，转成文本；
   给了 null 就保持 null。一个字段抽风不影响其他字段。
3. 全都失败：提示识别失败并保留模型原文，表单照常打开让我手填，不阻断。

所以遇到「识别出来一半字段」是正常的，缺的补上就行，不用重来。

## 界面导览

- 行程页：列表 + 搜索 + 筛选 chips + 右下角添加按钮。分区是「即将出发」和「历史」。

## 模拟器现状（重要，别浪费时间）

本机跑不了模拟器，根因只有一个：**AEHD 加速驱动没装，而它需要管理员权限**。

具体情况：

1. Android Emulator 的加速驱动（AEHD）没装。x86_64 镜像强制要求它。
   emulator-check.exe accel 返回 "Android Emulator hypervisor driver is not installed on this machine"。
   CPU 侧没问题：AMD Ryzen 7 7435HS，SVM 虚拟化在 BIOS 里是开的（VMFirmwareEnabled=True）。
   装 AEHD 需要管理员权限，助理没有。
2. 装不了加速就只能 -accel off 纯软件模拟，本机 15.7GB 内存、提交量已 12.7GB，
   QEMU 跑 API 37 镜像会卡住（进程活着但 CPU 时间停在 1.2 秒不增长）。

**ARM64 镜像这条路已经实测排除，不用再试**（2026-10-17）：

- 想法是 ARM64 全模拟不需要硬件加速。SDK 里确实有 qemu-system-aarch64.exe，
  也下载安装了 android-34 arm64-v8a 镜像（672MB，SHA1 校验通过），手工建好了 arm64 AVD。
- 但 emulator 启动时直接拒绝：
  "Avd's CPU Architecture 'arm64' is not supported by the QEMU2 emulator on x86_64 host."
  包装层硬编码了架构校验，不认非主机架构。
- 绕过包装层直接调 qemu-system-aarch64.exe 也不行：退出码 -1073741515（STATUS_DLL_NOT_FOUND）。
  四个 QEMU 二进制全部同样报错，说明它们只能在 emulator 注入的环境里跑，不能独立启动。

结论：没有第二条路，只能装 AEHD。

要修的话，以管理员身份开 PowerShell：
```
cd "$env:LOCALAPPDATA\Android\Sdk\extras\google\Android_Emulator_Hypervisor_Driver"
.\silent_install.bat
```
（这个目录没有的话，先在 Android Studio 的 SDK Manager 里搜
"Android Emulator hypervisor driver" 装上。）装完重启电脑，模拟器就能正常跑。

在没装驱动之前，用 Robolectric 测试和真机来验证，见上面「怎么跑」。

## 数据存哪

- 数据库：应用私有目录 databases/triplog.db，表 trips
- 图片：应用私有目录 files/tickets/ticket_<时间戳>.jpg，长边压到 1568px、JPEG 85
- 配置：EncryptedSharedPreferences，文件名 triplog_secure_prefs
- 备份：zip 内含 data.json（全部行程）+ tickets/（车票图），json 里只存图片文件名

全部在本机，没有任何自建服务器，不发任何遥测。

## 已知限制（当前版本）

- 筛选是客户端内存过滤，行程量大（几千条）后会卡，量大再改 SQL。
- 统计的车站/城市按文本精确匹配去重，「上海虹桥」和「上海」算两个地方，
  不做地理编码（自用场景够，要精确再引地名库）。
- 票价统计只认数字部分，「免费」这类不计入。
- 没有桌面小组件。
- 图标是占位矢量图（白底墨蓝火车头），要正式图标再换。
- 模拟器跑不了，只能用真机验证，详见上面「模拟器现状」。
